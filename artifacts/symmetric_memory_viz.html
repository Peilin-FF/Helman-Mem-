Symmetric Trust Memory — what the model actually learns

Three interactive panels for the per-peer state M_p, its update rule, and the address vector φ. Everything is computed live in the browser — the eigenvalues, eigenvectors and matrices you see are real (Jacobi eigensolver), not pre-rendered numbers. Drag, feed events, and watch the spectrum move. Companion to symmetric_memory_design.html.

the object

Each peer carries a symmetric matrix M_p = M_pᵀ, updated once per outcome event:

M_p  ←  γ·M_p  +  η·s·φφᵀ

γ∈(0,1] decay (how long memory lasts) · η write strength · s∈[-1,1] "how good" (the judge's verdict) · φ "good at what" (the task/aspect address). The read at decision time is the steering direction steer_p = M_p·φ*.

Note on size. In the real method M_p is 16×16 (rank: 16 in configs/symmetric_memory.yaml). The panels below use 4–8 dims only so the heatmaps and spectra are legible — every property (symmetry, Weyl bound, boundedness, eigenvector recovery) is dimension-independent; the small size is a teaching scale, not the method.

2 · The update rule, dissected

One event = decay the old + add a rank-1 evidence imprint. The imprint η·s·φφᵀ is the outcome "stamped" along the competence direction φ: it's literally the matrix you get by writing φ down a column and across a row and multiplying — so it's always the same fixed pattern, just scaled by how good the outcome was (η·s, positive deepens it, negative carves the opposite). It is symmetric for any φ (that's why M stays symmetric with zero enforcement cost). Set φ, s, γ, η and watch the three terms combine.

Two things to notice. (1) The imprint is always a perfect ± copy of the same pattern φφᵀ — it only ever pushes along the φ direction. Two events with the same φ stack; two with different φ build off-diagonal structure. (2) Apply the same event repeatedly: M′ does not run away — decay pulls it back, converging to the bounded steady state. This is Weyl's inequality in action: one event moves every eigenvalue by at most ‖imprint‖ = η.

3 · φ — the soft-prototype address

φ answers "good at what". It must collide (same task → same direction, or no eigenvalue ever accumulates) yet stay open (an unseen task still lands somewhere meaningful, so trust transfers). The fix: fixed per-task centroids C, and φ = soft-mixture of them by similarity. Drag the query.

Drag the ● query. Dots = fixed task centroids C (the CM's mean hidden per training task). The address is a softmax over cosine similarity.

Drag onto a centroid (low τ): one weight → 1.0, the rest → 0. A seen task resolves to its own direction, so repeated successes reinforce one eigenvector. This recovers the reliable per-(peer,task) behaviour.

stay open

Drag between centroids: the address is a mixture. An unseen / related task borrows trust from neighbours — that's the +23pt held-out-task transfer. Raise τ to see it smear; lower τ to sharpen (the open-work knob).

4 · The payoff a scalar can't match — recover signal from noise

A stream that is ⅓ consistent signal (same φ) and ⅔ noise (random φ, random sign). A scalar EMA averages signal and noise into one muddy number. The matrix sorts them: signal → top eigenpair, noise → bulk. Watch it happen.

The result: even buried 2:1 in noise, the top eigenvector locks onto the true reliability direction (alignment → ~1.0) and the top eigenvalue lifts clear of the bulk. This is the one thing a scalar reputation can never do — it has no eigenvectors to separate "good at X" from "random luck".

5 · The steering read — how M_p·φ* bends the CM's choice

This is the step that actually drives selection, and the one text explains worst. The trust matrix is not a number added to a logit. It produces a direction steer_p = M_p·φ*; a trainable W_up lifts it to hidden size, a learned gain g scales it, and δ = g·W_up·steer_p is added to the frozen CM's residual stream — so the CM re-scores the candidates itself under the nudge.

Three candidate peers on the current task φ*. Each peer has accumulated a different matrix; raise the gain and watch the CM's endorsement log-probs re-rank. (Matches ActivationSteerer in symmetric_memory.py: add = gain·proj(steer_vec), gain inits at 0.)

At g=0 the steered CM is bit-for-bit the frozen base (its raw prior). As g rises, each peer's bar moves by g · ⟨w_endorse_j , W_up·M_p·φ*⟩ — the peer whose matrix aligns with φ* climbs. g<0 inverts the read: the same evidence now pushes the aligned peer down. gain is an unconstrained learned scalar (init 0), so its sign is learned too.

φ* is fixed to "this task's competence direction" — Gemma's matrix has a big eigenvalue there, Qwen's points elsewhere, Phi's is near-empty. So as the nudge turns on, the CM's own choice flips from its flat prior toward Gemma.

Why a direction beats a scalar bias. Because RMSNorm sits before Q/K/V, adding a constant δ to the residual is not a uniform logit offset — it re-centres and re-scales per token, so one learned direction yields a context-sensitive re-ranking. The dropped scalar φ*ᵀM_pφ* bias could only push every score by a fixed amount, and proved too weak (§6).

6 · Joint matrix G over agents proposed

Status — read this first. The shipping method is independent per-peer M_p. G exists in code (update_joint, joint_redundancy in symmetric_memory.py) but is an ablation switch, default use_joint: off, and the current K-choose-1 endorsement read never consumes it. It is simulation-validated, not yet a run-vs-run result. This panel shows what G would capture if turned on — it is the genuinely-multi-agent claim, not current behaviour.

Per-peer M_p lives in context space ("is p good at this task?"). G lives in agent space — the CM's private coordination memory: G ← γ·G + η·ooᵀ, where o[p]∈{+1,−1,0} is each peer's outcome. Off-diagonal entries are the thing a per-peer matrix (or a scalar) cannot represent.

Team objective on G: pick subset S maximizing Σ trust(p) − λ·Σ G[p,q] — reward reliable agents, penalize redundant pairs, favour complementary ones. That turns "who defers to whom / redundancy / disagreement" into a computable objective. Weyl still holds (G symmetric), so one odd joint outcome shifts the relationship structure by ≤ η.

Honest caveat: ooᵀ captures only pairwise (2nd-order) structure; true 3-way coalitions need a tensor (skipped). On i.i.d. task streams the off-diagonal stays ≈0 — it only wakes up when agents have real complementarity, which is exactly the multi-aspect world below.

7 · The multi-aspect world — where the matrix finally earns its keep proposed direction

The reason §15 found M_p ≡ a scalar bank: three task-types give no latent, overlapping sub-structure for eigenvectors to discover. A real swarm has exactly that — the CM decomposes a task into aspects (search / revise / file / verify), routes peers per-aspect, and each (peer, aspect) outcome is its own event. Aspects overlap and recur across tasks, so the eigenvectors discover real competence axes.

Each peer specializes in some aspects. Feed decomposed tasks and watch each peer's matrix grow a top eigenvector that names the aspect they're reliably good at — a learned specialization a scalar reputation cannot hold.

aspects: searchrevisefileverify

The discovery: after the stream, each peer's top eigenvector points at the aspect they handle well (the highlighted bar), and the eigenvalue says how strongly. At decision time, a task needing aspect φ* steers up the peer whose eigenvector aligns — per-aspect routing, not one global score. This is also where joint G (panel 6) wakes up: search→revise→file are genuinely complementary roles, so G's off-diagonal finally carries signal. All four pieces (s, φ, the read, G) upgrade together — the open build cost is a dataset with aspect-decomposed tasks + per-aspect quality labels.
